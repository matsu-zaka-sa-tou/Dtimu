🛠️ 方案一：通过 P/Invoke 调用 libav* 动态库（最灵活）
这是最直接的方式。你通过 apt install ffmpeg 安装的系统包，已经包含了 libavcodec、libavformat 等所有 libav* 动态库（.so 文件）。你的 C# 项目可以通过 P/Invoke（平台调用） 直接调用这些库的 C 函数。

核心工具：FFmpeg.AutoGen
这是一个为 C#/.NET 自动生成的 FFmpeg 不安全绑定库，它把 FFmpeg 的 C API 完整地暴露给了 C#。

如何使用：通过 NuGet 安装 FFmpeg.AutoGen，然后在代码中设置 ffmpeg.RootPath 指向系统库的路径（通常在 /usr/lib/x86_64-linux-gnu/）。之后你就可以像调用普通 C# 方法一样，调用 avcodec_send_packet 等函数了。

与 AOT 的兼容性：FFmpeg.AutoGen 本身是纯 C# 绑定，理论上与 Native AOT 兼容。但因为它大量使用了指针和 unsafe 代码，你需要确保你的 AOT 编译配置允许不安全代码，并且能在裁剪（Trimming）时保留必要的 P/Invoke 方法。

优化的选择：Sdcb.FFmpeg
这是 FFmpeg.AutoGen 的一个分支（Fork），它在底层 API 上做了一些优化，比如使用标准的 [DllImport] 而非 LoadLibrary，并简化了枚举命名。它对 Linux 下的系统 FFmpeg 库支持很友好，会提示你使用 apt 安装对应版本的 FFmpeg。

🚀 方案二：使用支持 NativeAOT 的高级封装（最省心）
如果你的目标是快速集成，不想处理底层指针，可以选择专门为 NativeAOT 优化过的高级封装库。

FFMpegCore.NativeAOT
这是一个专门为支持 NativeAOT 和裁剪而修改的 FFMpegCore 版本。FFMpegCore 本身是一个流式 API 封装库，让你能用链式调用构建 FFmpeg 参数，而不是拼接复杂的命令行字符串。

优势：它内置了对 NativeAOT 的支持，你不需要担心 P/Invoke 的裁剪问题。

注意：这个包目前是 预览版（preview），在生产环境使用前需要评估其稳定性。

📞 方案三：通过 Process 调用 ffmpeg 可执行文件（最通用）
这是最简单、兼容性最好的方式，也完全符合你“不编译”的要求。系统安装的 FFmpeg 包含一个独立的 ffmpeg 可执行文件。

实现方式：在你的 AOT 编译后的 C# 程序中，使用 System.Diagnostics.Process 启动 ffmpeg 进程，并传入你构建好的参数。

与 AOT 的完美兼容：这种方式完全不涉及 P/Invoke，因此与 Native AOT 是100% 兼容的。你的 C# 代码只负责启动进程和读取输出，所有复杂的音视频处理都由外部 ffmpeg 程序完成。

适用场景：对于你“转码成多码率 HLS”的需求，这种方式尤其合适。你的 C# 程序可以充当一个任务调度器，监控文件、构建 FFmpeg 命令、启动进程、监控进度并管理输出文件。这比直接调用 libav* 库要简单稳定得多。
