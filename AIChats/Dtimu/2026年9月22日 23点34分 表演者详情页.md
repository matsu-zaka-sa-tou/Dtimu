## 一、目标

把「歌手页面」做进自写网络播放器，API 走 `PerformancerController`，前端沿用 `Album/Detail.cshtml` 的处理模式（PJAX、批量元数据、`MvPlayer` 播放入口、`player:change` 高亮），同时补上两个缺失：

1. 专辑页 / 歌手页都缺「播放全部」。
2. 歌手页曲目没有专辑封面。

中途还修了三个导致「播放不了 / 加载失败」的 bug。

## 二、后端

### `PerformancerController.cs`

```csharp
public class PerformancerController : Controller
{
    public IActionResult Detail([FromQuery] string name)
    {
        ViewBag.Name = name;
        return View();
    }
}

[ApiController]
[Route("api/performancers")]
public class PerformancerApiController : ControllerBase
{
    [HttpGet]
    public IActionResult Get([FromQuery] string name)
    {
        if (string.IsNullOrWhiteSpace(name))
            return BadRequest(new { error = "需要名字" });

        var performers = Program.DireInfo?.Performers;
        if (performers == null || !performers.ContainsKey(name))
            return NotFound(new { error = "未找到该歌手", name });

        return Ok(performers[name]);   // string[]，hash 列表
    }
}
```

要点：

- 路由用 `?name=` 查询串，不用路径参数，避免 `/` `#` `?` 破坏路由。
- `ContainsKey` + `NotFound` 容错，防止字典直接索引抛 500。
- 返回 `string[]`，元数据交给 `/api/Lists/MusicList?hashes=...` 批量取。

## 三、前端歌手页 `Performancer/Detail.cshtml`

结构与 `Album/Detail.cshtml` 同构，只把「专辑」换成「歌手」：

### 数据流

```
GET /api/performancers?name=xxx
   → string[] hashes
   → fetchMusicMap(hashes) 批量取 /api/Lists/MusicList?hashes=...
   → CoverUtil.buildHashToCoverMap() 反查 hash → 专辑封面
   → render(root, hashes, musicMap, coverMap)
   → 构建 _queue（含 hash / url / title / artist / cover）
   → 渲染单曲列表 + 播放全部
```

### 关键函数

| 函数 | 作用 |
|---|---|
| `init()` | 拉数据、拿元数据、拿封面映射、调 `render` |
| `fetchMusicMap(hashes)` | 按 `MUSIC_BATCH_SIZE = 20` 分批请求 `MusicList`，合并结果 |
| `render(root, hashes, musicMap, coverMap)` | 构建 `_queue`、清空 root、画「单曲 (N) + 播放全部」+ list |
| `buildMusicItem(hash, i, musicMap)` | 单行：序号 → 缩略图 → 标题 → 演出者链接 → 文件名 → 两个按钮 |
| `playAt(i)` | `MvPlayer.playOrInsert(_queue[i])`，播放或插入 |
| `playNextAt(i)` | `MvPlayer.playNext(_queue[i])`，只插队不切歌 |
| `onPlayerChange(e)` | 监听 `player:change`，切换每行的播放/暂停图标 |

### 演出者链接

- 顶部演出者区块和曲目内的徽章都改成了 `<a href="/Performancer/Detail?name=...">`，类 `performer-link`，hover 有反馈。
- `encodeURIComponent(p)` 编码，避免特殊字符。

### 播放全部

- 曲目区块 header 用 `sectionHeader('单曲 (N)', actions)`，右侧挂按钮。
- 按钮点击调 `window.MvPlayer.playAll(_queue)` —— 依赖下面 `MvPlayer` 的扩展。

### 曲目缩略图

- 曲目行左边插 `<img class="track-thumb">`，URL 来自 `_coverMapByHash[hash]`。
- `_coverMapByHash` 是 IIFE 作用域变量，`init()` 里赋值，`buildMusicItem` 读。

## 四、全局封面系统 `CoverUtil`

从 `MusicCard/Default.cshtml` 抽到 `_Layout.cshtml`，`<body>` 后立刻加载。

### 暴露接口

```js
window.CoverUtil = {
    generateCoverSvg,    // 文本 → SVG 字符串
    coverSvgDataUrl,     // 文本 → data:image/svg+xml;...
    coverUrl,            // item → 有 pictures 走 /Cover/{hash}，有 cover 直接用，否则 SVG
    pickColor,           // FNV-1a 哈希 → 14 色之一
    buildHashToCoverMap, // 从 AlumbList 反查 hash → 封面 URL
    clearCache           // 清空 SVG 缓存
};
```

### `buildHashToCoverMap()`

- 拉 `/api/Lists/AlumbList`，遍历每个专辑：
  - `pictures[0]` → `/Cover/{hash}`
  - 该专辑 `musics` 里的每个 hash → 映射到这个封面
- 用 `_hashCoverPromise` 做 Promise 缓存，整个 SPA 生命周期只请求一次。
- 找不到 / 失败时返回 `{}`，不阻塞页面。

### 与旧代码兼容

- `MusicCard/Default.cshtml` 删除了内联 SVG 生成器，`coverUrl` 改为 `window.CoverUtil.coverUrl(item)`。
- `window.generateCoverSvg` / `window.coverSvgDataUrl` 仍然保留，兼容旧调用。

## 五、播放器 `MvPlayer` 扩展

在 `_Layout.cshtml` 的播放器 IIFE 里新增：

```js
function setQueue(items, startIndex) {
    if (!Array.isArray(items) || items.length === 0) return;
    queue = items.slice();
    index = Math.max(0, Math.min(startIndex | 0, queue.length - 1));
    load(index, true);
    document.dispatchEvent(new CustomEvent('player:queue', {
        detail: { queue: queue.slice(), index: index }
    }));
}

function playAll(items) { setQueue(items, 0); }
```

挂到 `window.MvPlayer`：

```js
window.MvPlayer = {
    playOrInsert: playOrInsert,   // 播放/插入并播
    playNext: playNext,           // 只插到当前曲目之后，不切歌
    playQueue: ...,               // 原有
    getQueue, getIndex, toggle, next, prev, current, refresh,
    setQueue: setQueue,           // ★ 新增
    playAll: playAll              // ★ 新增
};
```

## 七、Bug 与修复

| Bug | 根因 | 修法 |
|---|---|---|
| `_Layout.cshtml` 播放器整个不工作 | `refresh: function () { updateUI(); }` 后缺逗号，IIFE 直接 SyntaxError | 补逗号 |
| 专辑页「曲目」渲染两次 | `if (performers.length)` 里塞了「曲目」header，后面又有一个独立曲目块 | 拆成三个独立 section |
| 歌手页「加载失败」 | `render` 函数花括号未闭合，后半段工具函数全被塞进 `render`，且缺少 DOM 构建逻辑 | 补上 `render` 收尾，工具函数挪到外面 |
| 歌手页「加载失败：_coverMapByHash is not defined」 | 建议代码里用了 `_coverMapByHash`，但变量从未声明 | 在 IIFE 顶部加 `let _coverMapByHash = {};`，`init` 赋值，`buildMusicItem` 读取 |
| 预览框悬停颜色变化（早期） | `pickColor` 用随机 + `coverUrl` 无缓存 | 改成 FNV-1a 哈希色 + `_urlCache` Map 缓存 |

## 九、关键设计原则

1. **URL 参数一律 `encodeURIComponent`**，避免特殊字符破坏路由。
2. **颜色用内容哈希**（FNV-1a），不是随机，同一输入永远同一输出。
3. **封面缓存**：`CoverUtil._urlCache` 按内容 key 缓存，`buildHashToCoverMap` 用 Promise 缓存。
4. **C# 是视觉规范，JS 是复刻**：14 色数组、字体顺序、0.68/0.72 系数、22/18/220/165 边距、25→15 缩放全部对齐。
5. **PJAX 清理模式**：每个页面 IIFE 里 `window.__xxxCleanup` 清理上一轮监听器，防止重复绑定。
6. **全局状态单一真相**：`queue` / `index` 只在播放器脚本里，其他模块通过 `MvPlayer.getXxx()` 或 `player:queue` 读取。
