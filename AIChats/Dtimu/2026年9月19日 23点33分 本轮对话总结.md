# 本轮对话总结

按时间线拆成六件事，每件都点出**为什么这么改**，而不只是"改成什么"。

---

## 一、navbar 右上角加状态图标（上传 / 光盘）

**需求**：`Program.IsBurned` 为 false 显示上传图标跳
        `/update`，true 显示光盘图标跳 `/about`。

**遇到的两个坑**：

1. **图标看不到** →
                   `_Layout.cshtml` 的 `<head>` 里没有
                       bootstrap-icons 的样式引用。`<i class="bi bi-upload">`
                       是靠字体渲染的，字体没加载出来就是个 0×0 的空标签。补一行 CDN `<link>` 解决；不想依赖 CDN
                       就改用内联 SVG。
2. **图标不跳转** → 页面里有
                       PJAX，点击逻辑是：

   ```js
   if (!shouldPjax(a)) return;
   e.preventDefault();          // ★ 先干掉浏览器默认跳转
   navigate(a.href, true);      // 再交给 PJAX
   ```

   而同源链接一定通过 `shouldPjax`，所以默认跳转**已经被 prevent 了**。接下来 PJAX
                       内部如果发现路由 404 或者响应 HTML 里没有 `#app-main`，它会静默
                   `return`——结果就是"点了没反应"。
   **修法**：给这两个 `<a>` 加
                   `data-no-pjax`。这是 PJAX 里预留的开关，命中后 `shouldPjax` 返回 false，`preventDefault` 不执行，浏览器走原生整页跳转，与 PJAX
                       完全无关。

**位置微调**：图标容器加
        `margin-right: 40px`——因为它被 `.navbar-collapse`
            的 `justify-content-between` 顶在最右，加右边距就是往左推。

## 二、播放列表抽屉（汉堡按钮 + 右侧滑出面板）

**结构决定**：

- **按钮**放
                  `Default.cshtml`（VC 里），成为 `.player-inner` flex 布局的一个子项 → 因为 QQ 音乐那种设计就是把列表按钮做进播放条。VC 只负责 HTML 片段，DOM 挂在哪都不影响脚本
                  `getElementById`。
- **面板**放
                  `_Layout.cshtml`，**在
                      `<footer>` 外面** →
                      原因只有一个但很重要：`.player-footer` 有
                  `position: fixed` + `z-index: 1030`，它会创建一个**局部堆叠上下文**。面板若放进去，它的
                  `z-index: 1040` 就只在这个上下文里比较，永远盖不过 footer 外的其他元素。放外面则相对全局算。

**状态同步机制**（重要设计）：

- 播放器脚本在**队列/索引变化**时派发 `player:queue` 事件，附带 `{ queue: [...], index }`。
- 抽屉脚本监听该事件 → 重绘列表或只更新高亮。
- 抽屉打开时通过
                  `MvPlayer.getQueue() / getIndex()` 兜底同步一次（应对 PJAX 切换后
                  `_lastKey` 未初始化的情况）。

**为什么不用 `player:change`**：那个事件在播放/暂停时也触发，用它重绘会导致"点一下暂停、抽屉滚动条跳回顶部"。区分"队列变了"和"播放状态变了"是关键。

**重绘条件用
            `key = queue.map(x => x.hash).join('|')`**：只有成员真正变化时才全量重绘
            DOM；索引变了只 `updateHighlight`。

## 三、Detail.cshtml 播放按钮语义改造

**需求**：点播放时——

- 队列空 → 当作第一首，播。
- 歌已在队列里 → 跳到那一首，播。
- 歌不在队列里 → 插到**当前曲目之后**，播。

**核心实现 `playOrInsert(item)`**：

```js
if (index < 0 || queue.length === 0) { queue=[item]; load(0,true); return; }   // 空
const existingIdx = queue.findIndex(x => x.hash === item.hash);
if (existingIdx >= 0) { /* 已在，跳到或切换 */ return; }                      // 已存在
queue.splice(index + 1, 0, item); load(index + 1, true);                       // 插入并播
```

**与 `playNext`（下一首播放）的区别**——这是本轮语义上最容易搞混的地方：

| 方法 | 语义 | 行为 |
| --- | --- | --- |
| playOrInsert | "播放这首歌" | 插入后立即播 |
| playNext | "下一首播这首歌" | 只插入队列，不切歌 |

两者都保留，用途互补。Detail 页的"播放"按钮走 `playOrInsert`，新的"+号"按钮走 `playNext`。

**按钮的 UI 变化**：原来每行一个播放按钮，现在两个（`ICON_NEXT`
            加号在左，`ICON_PLAY` 在右），用 `d-flex gap-1`
            包起来。

**"当前曲目"高亮靠 `_index` 而不是 hash
                比对**：为了未来允许队列里出现重复 hash 时仍准确（虽然当前 `playNext` 会去重）。

## 四、抽屉按钮从"浮空"改到"播放条内"

**原方案**：`.playlist-toggle` 用
        `position: fixed; right: 16px; bottom: 96px` 浮在页面右下角。

**改成**：放进
        `.player-inner` 末尾的 `.player-extra` 里，成为 flex
            子项。

**CSS 层面的彻底改写**：

```css
/* 原来 */
.playlist-toggle { position: fixed; right: 16px; bottom: 96px; border-radius: 21px; ... }

/* 现在 */
.playlist-toggle {
    width: 38px; height: 38px; border-radius: 8px;
    background: none; border: none; color: #333;
    /* 不再有任何 position */
}
```

**副作用**：`body.playlist-open .playlist-toggle` 原来是
        `opacity: 0` 隐藏按钮（因为浮空按钮会挡面板）。现在按钮在播放条里不挡面板，改成**高亮**：

```css
body.playlist-open .playlist-toggle {
    background: #eaf2fb;
    color: #1b6ec2;
}
```

## 五、小屏按钮"消失"的真实原因

**症状**：手机宽度下，播放条最右边的列表按钮看不见。

**误诊**：以为是某个
        `display: none` 隐藏了它。

**真相**：它被**挤出视口**了。flex 布局里：

- `.player-center` 的
                  `flex: 1` 是看起来能缩，但 flex item 默认
                  `min-width: auto` —— **不会小于内容宽度**。它的内容是两个 40px 时间戳 + range + 间隙，最小 ~176px。
- `.player-info` 是
                  `width: 260px` + `flex-shrink: 0`。
- 两者加起来就 400px+，320/360 屏上，被顶在最后的
                  `.player-extra` 就出视口了。

**修法**（全在小屏媒体查询内）：

1. `.player-info` 从
                   `width: 140px` 改成
                   `flex: 0 1 auto; max-width: 110px; min-width: 0` ——
                   **允许收缩**。
2. `.player-center` 加
                   `min-width: 0` —— 允许压到内容宽度之下，range 自动变短。
3. `.player-meta` 加
                   `min-width: 0` —— 长歌名用省略号，不再撑开父级。
4. 各类 `gap` /
                   `padding` / `font-size` 在小屏压缩。
5. 音量整块 `display: none`。

**结果**：最窄需求从 ~380px 降到
            ~280px，320px 屏上按钮稳稳可见。

## 六、反复出现的一个设计原则

这三处改动（状态图标、列表按钮、播放逻辑）碰到的是同一个东西：**PJAX +
                全局播放器 + VC 组件三者交叠时的边界**。归纳几条：

1. **PJAX 只替换 `#app-main`**，任何在它之外的 UI（导航栏状态图标、播放条、抽屉面板）在 PJAX 切换时都**不会重渲染**。

   - 好处：播放不断、抽屉不闪。
   - 代价：服务端状态（比如 `IsBurned`）改变后图标不会自动更新，得靠 `pjax:load`
                                 事件手动同步（如果真有这个需求的话）。
2. **导航到不包含 `#app-main`
                           的页面**时，PJAX 会静默放弃并**吞掉点击**。要么给链接加 `data-no-pjax` 走原生跳转，要么确保目标页面也带 `#app-main`。
3. **`position: fixed` +
                       `z-index` 会创建局部堆叠上下文**。想让某个元素相对全局排层级，它就不能放在有 `z-index` 的祖先里。
4. **VC 只负责 HTML**。按钮放
                       VC、面板放 Layout、CSS 全在 Layout 的 `<style>`，脚本一行不用改——这是本轮最省事的分工。
5. **全局状态（`queue` /
                       `index`）只能有一份真相**，就在播放器脚本里。其他模块（抽屉、Detail）都通过 `MvPlayer.getXxx()` 或
                   `player:queue` 事件**读取**，不自己维护副本。
